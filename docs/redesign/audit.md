# AskHermie redesign audit

## What was getting in the way

| Area | Finding | Redesign |
| --- | --- | --- |
| Identity | The dark gradient, glowing mascot artwork, glass navigation, scrolling labels, and blocks of achievement statistics made the site look like an agent product pitch. The introduction took most of the first desktop screen before showing what a visitor could use. | A warm paper palette, serif masthead, one electronics still life, and a visible workshop index. The image is generated editorial art. It depicts a generic workbench. |
| Site structure | The repository contained three Astro pages. The README listed four more. Requests for those four paths returned the homepage with a 200, creating the appearance of pages that did not exist. | Each planned URL now has a purpose. Resources is the full catalog, Tools starts from the visitor’s task, Lab offers exercises, Skills records Hermes integrations, and the Build Log documents outcomes. A custom 404 gives incorrect URLs a proper landing page. |
| Content and credibility | The homepage still reported 109 resource cards and described RimSort #2286 as open. The live catalog displayed 631 entries, including repeats. Some concepts, such as Lantern and Network Device Investigator, appeared only as plans. | Removed stale counters and verified the RimSort merge, WinUtil closure, and home-llm fork commit. Used existing catalog tools for exercises and recommendations. The skills catalog starts with one documented third-party plugin. |
| Repository | Astro rendered three pages with duplicated navigation and footer markup, a homepage Svelte island, a tightly coupled catalog, and a stylesheet of 3,439 lines. The repository also held 87 discovery and research notes that provided sourcing and screening context. | Shared Astro layout and metadata, a shorter stylesheet, and a Svelte search island that enhances static catalog entries. Discovery notes and the existing catalog source location are preserved. |
| Accessibility | Desktop and 390 px mobile rendered without horizontal overflow. Catalog card titles used h2 below group h3 headings, group buttons had no programmatic selected state, and the result count had no live announcement. The page lacked a skip link. | Added a skip link, readable focus treatment, current-page indicators, native search and filter controls, live result and clipboard feedback, and keyboard-operable disclosures. Static entries still open with JavaScript disabled. |
| Search and performance | The live catalog shipped 2.44 MB of uncompressed HTML. It included a complete set of entries in both rendered markup and serialized island props, plus a large list in JSON-LD. The public asset directory included multiple large versions of the same artwork. | Filters read static entry text in place, the oversized JSON-LD is now concise collection metadata, and the homepage loads no Svelte island. Fonts are self-hosted and the homepage uses one compressed WebP. Existing legacy asset URLs remain available. |
| SEO | The original pages had canonical URLs, social metadata, and a sitemap. The sitemap listed only three routes with stale dates. The app fallback made missing URLs look successful. | Shared canonical and social metadata, a generated sitemap covering all public routes, updated robots-facing page inventory, and a noindex 404. |
| Deployment | The repo is static Astro with Svelte and plain CSS. GitHub’s production commit reported a successful Cloudflare Pages check, and the Pages project hostname served the same homepage as the custom domain. GitHub write access was verified. Wrangler has no authenticated Cloudflare session in this environment. | Build output remains `dist`. The PR uses the repository’s existing Pages integration for a branch preview when available. |

The remaining catalog entries retain their discovery-sourced descriptions and commands. This redesign reviewed and rewrote the site copy and selected catalog entries. It did not execute every third-party installation or validate every upstream URL.

## Three directions considered

1. **Workshop field guide.** Warm paper, an editorial serif, dark green ink, a single hardware photograph, and ruled lists. This lets reference entries remain dense and easy to scan while giving the site a recognisable identity. Julia Evans’s plain-language technical index and Low-tech Magazine’s practical topic framing informed the approach. [Julia Evans](https://jvns.ca/) · [Low-tech Magazine](https://solar.lowtechmagazine.com/)
2. **Developer notebook.** A date-led homepage with tags, search, links, and short notes, taking cues from Simon Willison’s weblog. It would make publishing frequent work easy and place contribution history centre stage. AskHermie currently has a much deeper catalog than it has dated write-ups. [Simon Willison’s Weblog](https://simonwillison.net/)
3. **Project lab.** A visual index organised by devices or experiments, with annotated project photographs and more space for build records. Hundred Rabbits’ technology projects and documentation exemplify the appeal of an identifiable practice. For AskHermie, the approach would need a larger body of documented builds and original images. [Hundred Rabbits](https://hundredrabbits.itch.io/)

**Selected the workshop field guide.** It can give hundreds of resources a consistent structure and still make room for single-purpose exercises and evidence-backed build notes. Its strongest visual element can be illustrative without making claims about hardware the workshop has built.
